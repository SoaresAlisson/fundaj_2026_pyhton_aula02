Parte 1 — Semântica básica da linguagem

Variáveis

“Quando fazemos uma atribuição a uma variável (ou a um nome) em Python, estamos criando uma referência ao objeto do lado direito do sinal de igualdade.” (McKinney, 2017, p. 68)

nome = "Leo"           # String (Texto)
idade = 7              # Integer (Número inteiro)
altura = 5.6           # Float (Número decimal)
eh_gato = True          # Boolean (Booleano/Lógico)
defeitos = None        # None type (Tipo nulo/vazio)

Convenções para variáveis:

  • Não comece nomes com números, não use espaços nem ponto, use sublinhado _ para separar palavras
  • variáveis são escritas em snake case: bla_bla
  • Usar nome significativo, ao invés de “a”, “b”

Por que isso importa para análise de dados?

“Compreender a semântica das referências em Python, e quando, como e por que os dados são copiados, é particularmente crucial quando estivermos trabalhando com conjuntos de dados maiores em Python.” (McKinney, 2017, p. 68)

Aviso

Cuidado ao “copiar” um DataFrame com df2 = df1: geralmente é uma referência. Para uma cópia de verdade, use .copy() (veremos na aula de pandas).

Comentando código em Python

“Qualquer texto precedido pelo sinal de sustenido (#) será ignorado pelo interpretador Python. Com frequência, ele é usado para adicionar comentários ao código.” (McKinney, 2017, p. 66)

  • Python tem um único marcador de comentário: o #.
  • # vale do símbolo até o fim da linha.
  • Não existe comentário de múltiplas linhas “oficial” (como /* */ em C) — usam-se vários # ou docstrings (ver adiante).
# isto é um comentário em linha própria
x = 5  # comentário após o código também funciona
# isto é um comentário: o interpretador ignora a linha inteira
x = 5  # comentário após o código também funciona
print(x)
5

Comentando código para “desligar” linhas

Uma prática comum e útil: comentar blocos para desativar código sem apagar (o McKinney cita isso como exemplo na p. 66):

results = []
for line in ['foo bar', 'baz']:
    # mantém as linhas em branco por enquanto
    # if len(line) == 0:
    #     continue
    results.append(line.replace('foo', 'bar'))
print(results)
['bar bar', 'baz']
  • As linhas # if len(line) == 0: e # continue ficam “desligadas”.
  • Atalhos de teclado: no Jupyter/Colab, Ctrl+/ (ou Cmd+/ no Mac) comenta/descomenta a seleção.
  • No VS Code: Ctrl+/ também; no RStudio com Python: Ctrl+Shift+C.

Onde colocar o comentário

# ANTES do código: descreve a intenção do bloco
results = []
for line in ['a1', 'a2']:
    results.append(line)  # DEPOIS: documenta a linha específica
print(results)
['a1', 'a2']

“Comentários também podem ocorrer após uma linha de código executado. Embora alguns programadores prefiram colocar os comentários na linha que antecede uma linha de código em particular, colocá-los depois às vezes pode ser conveniente.” (McKinney, 2017, p. 66)

  • Antes: explique o porquê do bloco (a intenção, a decisão).
  • Depois: detalhe uma linha específica, sem virar tradução literal do código.

Docstrings: documentação “de verdade”

Docstring é a primeira string de uma função/módulo/classe, usada pelo help():

def estatisticas(vals):
    """Devolve (mínimo, máximo, média) de uma sequência numérica."""
    return min(vals), max(vals), sum(vals) / len(vals)

help(estatisticas)
Help on function estatisticas in module __main__:

estatisticas(vals)
    Devolve (mínimo, máximo, média) de uma sequência numérica.
  • Aspas triplas """..."""; não é comentário: o Python guarda e o help() mostra.
  • # = nota para quem lê o código; docstring = documentação para quem usa a função.
  • Convention: uma linha curta; se precisar de mais detalhe, linhas seguintes com parâmetros e retorno.

Bom vs. mau comentário

# MAU: repete o que o código já diz (ruído)
i += 1  # soma 1 ao i

# BOM: explica o porquê, o contexto, a fonte
i += 1  # pula o cabeçalho do CSV (linha 1 é o header)
# valores imputados com a média do IBGE 2010 (ver docs/receita.md)
renda[renda.isna()] = renda.mediana

Dica

Regras de bolso para a análise de dados: - Comente decisões (“por que descartar essas linhas?”), não sintaxe. - Cite a fonte do dado ou do critério (documentação, relatório). - Use # TODO: para marcar o que falta; o pass do slide anterior é um caso. - Se o código precisa de MUITO comentário para ser entendido, considere renomear variáveis ou quebrar em funções — código claro < comentário compensatório.

Fatiamento (slicing)

seq = [7, 2, 3, 6, 3, 5, 6, 0, 1, 9]
print(seq[1:5])    # índices 1 a 4 (fim exclusivo)
[2, 3, 6, 3]
print(seq[:5])     # do início
[7, 2, 3, 6, 3]
print(seq[5:])     # até o fim
[5, 6, 0, 1, 9]
print(seq[-4:])    # 4 últimos (índice negativo conta do fim)

print(seq[::2])    # passo 2: elementos alternados
[7, 3, 3, 6, 1]
print(seq[::-1])   # passo -1: inverte!
[9, 1, 0, 6, 5, 3, 6, 3, 2, 7]
